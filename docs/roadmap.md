# 路线图

状态：路线草案形成于 2026-09-24；工程进展更新于 2026-10-07。本文是开发计划，不是结果报告或付费调用授权；工期和费用均为估算。

当前工程进展：P0 离线机制已实现，新增非流式 provider 契约、合成响应检查与缓存测量方案；完整 M1 及真实 M2–M5 尚未完成。入口与验收见 [ADC 研究](../research/adc/README.md)。

## 项目身份

**先复现与验证，再把验证成立的机制做成可用产品。**

研究起点是 Hajidehi、Wang、Idreos 的 [arXiv:2608.31082v2](https://arxiv.org/abs/2608.31082v2)：回答代理打开文档后，从已加载的上下文分叉 cracking 子代理，依据当前及此前查询推测可复用的实体、属性与关系；验证并保存带证据的对象，后续相关查询先看目录、读对象，缺失时回退原文。v1 称 agentic data cracking（ADC），v2 更名为 agentic context cracking（Acc）；下文用“cracking”，保留已有实验 ID 中的 adc。

v0.1.0 是财报数字问答与可验证复用的产品原型，不是该论文的复现：它使用白名单实体/指标和针对当前缺失需求的抽取，尚无开放关系、推测性抽取、文档查询历史、列表基数与多跳代理循环。已有账本、验证和恢复结果仍有价值，但不能替代上述机制的验证。在新报告完成前，README 的实测结果仍只描述 v0.1.0。

## 开发原则

1. **检验主张，不追求逐项照搬。** 已检索的公开材料未找到论文的完整实现及提示词；合理偏差、解释性实现与扩展分别声明，不承诺复现论文的具体百分比。
2. **历史决策仅供参考。** 不让既有 Go 流程、指标白名单、HOT_ONLY、单一模型或旧 100 CNY 额度决定研究设计；也不在文档任务中擅自修改这些运行配置。
3. **预算可以合理提高。** 样本量先服务于问题和统计需求，再用试点估算执行成本；按阶段批准金额、请求数和并发，不能事后追认超支。
4. **双口径报告。** 测试题成本与全序列成本并列，分别列回答路径和 cracking。只有复用阶段便宜时，只能称“复用阶段降本”，不能称整个工作负载降本。
5. **区分证据类型。** mock/真实、试点/独立主集、首次构建/后续复用、估算/计费记录分开。没有显著差异不等于质量等价。
6. **隔离信息和状态。** 回答/cracking 不得看到未来问题、金标、分解、必要证据清单或评分。研究数据不进入产品事实表；GROUNDED 只表示机械证据校验通过，不代表语义正确。
7. **失败也交付。** 保存失败、未知费用、拒绝和无法判定，不能只交付支持假设的结果。

## v0.2：FanOutQA 概念复现

用户已确认：文件系统式搜索/整页读取（超长页面确定性分页），Luna 主实验、Flash 复核。规模修订为从 dev 的 310 题中确定性选取 **210 题：12 题试点 + 198 题独立主实验**；剩余 100 题保留，不用于调参或自动追加。每题另生成 1 道相关题，因此 210 指原始目标题数，不是调用数。

- 模型入口：OpenRouter；Luna 使用 `openai/gpt-6-luna`，Flash 使用 `deepseek/deepseek-v4.1-flash`，不是官方直连的 `deepseek-flash` 标识。
- 相关题生成改为 `anthropic/claude-opus-5.5`；评审候选为 `google/gemini-3.8-flash`、`qwen/qwen3.8-flash`，GPT-4o 保留为上游兼容性对照。先用试点和人工标签校准，再冻结主 judge，不凭价格或通用榜单确定可靠性。详见[模型选型调研](replication/model-selection-v1.md)。同一 OpenRouter key 可认证，但目录可见不等于账户通过真实调用验收。
- 独立 Python 研究 harness + SQLite 对象库，不先改 Go API 或产品数据库。先把因果比较和计费观测做清楚，再移植到产品。
- 核心对照：B0（无 cracking）、T0（只抽当前需求）、T1（推测性 cracking）。Flash 的同模型复核与跨模型读库是两个不同实验。

详见 [开发计划](replication/v0.2-plan.md)、[M0 协议](replication/protocol-v1.md)及[机器可读参数](../eval/replication/fanoutqa-v1/protocol.json)。后者是 **PLANNED 草案，不是可直接执行的已批准配置**。

## v0.3：金融领域验证

M6 后根据成本、质量、对象正确性和使用场景共同决定是否推进；若关键主张失败或无法判定，优先解释机制和测量问题，不直接扩展产品。

- 使用官方来源的多公司、多年度年报；独立构建并冻结金标，不分发完整原文。
- 设计主题调查序列（可参考 20 道预热 + 10 道测试），但不能称为复现论文未公开的 Hitchcock 题集。
- 比较机械 GROUNDED 对象与经过领域语义验证的 VALIDATED 对象，测量准确率、对象错误率和验证成本。
- 验证跨时间、跨模型复用；区分供应商 prompt cache 与持久对象库。
- Go 财务验证器是候选升级插件，不要求复制旧白名单设计。预算与信任策略另行冻结。

## v0.4：产品化

- 按已验证的接口移植开放对象、目录、受限读取、版本/权限隔离及异步构建；[移植注意事项](replication/v0.2-plan.md#product-port)。不现在预占迁移号。
- 调查工作台展示每份文档的主体–关系、基数、证据、时效和信任等级，明确机械校验不等于语义验证。
- 默认不把仅机械校验的对象当成已验证事实发布；最终信任策略依据 v0.3 证据另行决定。
- 实测费用与估算的反事实节省分开；补齐故障恢复、访问控制、导出及部署验收。

## 既有工作如何处理

检索相关实验分支、M3/M4 调度恢复、白名单和产品界面都是可参考资产，不是 v0.2 的前置依赖。本轮不合并、删除或修改这些分支，不永久冻结后续选择。优先修必要缺陷，其他产品扩展在研究结论明确后重新排期。

保留有价值的方法：预留/结算及 UNKNOWN 停派、实验冻结、提交/产物哈希、信息隔离、公开源检查、首次构建与复用分账。详见[实验记录模板](experiments/template.md)。

## 主要风险与决策关口

| 风险 | 处理 |
| --- | --- |
| 论文未明确公开 split、完整代理与 store 调度 | 声明解释性实现；主要研究结论受该偏差限制 |
| Wikipedia/题集可能进入模型训练 | 记录无打开作答和证据覆盖；不能据此证明或排除记忆；金融扩展检验外部有效性 |
| 历史正文 + 当前检索索引 | 固定 epoch、revid 和正文哈希，缓存检索结果；不能声称完整重建 2023 年检索环境或保证匹配每个 gold |
| OpenRouter 路由、参数转译、usage 或缓存变化 | 固定实际 endpoint/服务层、禁 fallback；M2 实测，不能由价格表推断缓存命中 |
| Luna >272K 输入价格档与额外 reasoning 输出 | 统一上下文策略、保留 reasoning 用量；不把按价格表重算当另一模型实测 |
| 相关题人工核验和列表语义完整性 | 核验先于回答运行；模型声明完整的列表仍需人工审计 |
| 主集 198 组对小幅质量差异的统计功效有限 | 固定 5 个百分点的草案非劣效界限，报告配对区间与无法判定；不因缩小样本而放宽界限 |

M0 交付草案不代表冻结完成；M2 前批准烟测，M3 前批准生成，M4 前批准试点。M4 后冻结代码/工作负载/预算与全部未决参数才可进入 M5。每次修改保留原版本和原因，不倒改已运行的标准。
