# v0.2 开发计划：先验证 cracking，再接入产品

状态：PLANNED，2026-09-24。本文描述**待实现**的设计；此次仅交付文档和参数草案，没有新增 harness、数据库迁移或真实评测结果。研究范围、抽样和判定以 [M0 协议](protocol-v1.md)为准，总方向见[路线图](../roadmap.md)。

## 1. 范围与关键取舍

- 主路径：OpenRouter `openai/gpt-6-luna`；复核：`deepseek/deepseek-v4.1-flash`。模型替代是明确偏差，不以同价比推断同能力或同降本效果。
- 同一 FanOutQA 工作负载、相同基础工具与上下文策略，对比 B0、T0、T1；回答代理与 cracking 使用同一臂的模型配置。
- 独立 Python harness + SQLite，不绑定现有 Go 的财务需求、PDF bbox、预算币种和抽取 batch。工程复用不能先于实验可解释性。
- v0.2 不改默认产品路径、不发布研究对象到浏览器、不提供任意 SQL、任意 shell 或代码执行。文件系统式工具指受控的文档导航及每题笔记接口，不是宿主文件权限。
- M0 未决项明确留空，M2/M4 验证后冻结；文档不是已获准执行的运行配置。

## 2. 建议目录与边界

以下是 M1 的目标布局，**当前尚不存在这些实现**：

```text
research/adc/
  corpus/          # dated Wikipedia、正文/搜索缓存、不可变文档 manifest
  providers/       # OpenRouter adapter、mock、usage 归一化
  agent/           # 基础代理循环、工具、上下文管理
  cracking/        # fork、预算分配、schema、grounding、规范化
  store/           # SQLite、列表事务、目录、对象查询、查询历史
  accounting/      # 原子预留、结算、UNKNOWN、恢复/对账
  runner/          # 工作负载隔离、调度、恢复、冻结检查
  evaluation/      # FanOutQA scorer adapter、统计与对象审计
  prompts/         # B0/T0/T1、生成 prompt、schema 与版本
  tests/           # 无网络无密钥的离线测试
  requirements.lock
```

公开协议位于 `eval/replication/fanoutqa-v1/protocol.json`。原始数据、usage、响应、SQLite 与密钥放在仓库外、由 `CRACKRAG_RESEARCH_DIR` 指定的私有目录；key 仅从环境变量/私有 secret store 读取，不写入协议或日志。公开报告只引用审查后的汇总、哈希和可分发样本。

## 3. 最小闭环

```text
生成器：仅 Q_i + 生成规则 → R_i → 人工核验 → 冻结 workload

每个 (model, arm, group) 使用独立对象库：
  R_i 新会话 → search/open → answer continuation → 后台 cracking
  等待全部 forks 完成并持久化 → 保存 warm snapshot
  Q_i 新会话 → search + catalogue / read_objects → 缺失才 open
  保存回答 → 等待本题 forks → 封存全部调用和 store

评测进程：封存回答 + gold → 字符串评分 / 独立 judge → 统计报告
```

R/Q 之间只传持久对象及已发生的文档查询历史，不传 R 的回答、对话、笔记或整个上下文。Q 的文字直到 Q 开始才对代理可见。B0 也运行 R 和 Q，但没有跨题对象库，以便比较全工作负载成本。

### 3.1 语料与工具

1. 锁定 FanOutQA commit/数据哈希，复用其 Markdown 转换语义。正文按 `2023-11-20T00:00:00Z` 及之前最新可用修订读取，记录 `pageid, revid, title, source_url, retrieved_at, parser_version, content_sha256`；缓存键包括修订号和解析版本，不能只用 pageid。
2. 搜索使用当前 MediaWiki 索引，首个结果按规范化 query 缓存供各臂共用，记录时间、排序和结果哈希。不同 query 不保证一致，缓存不能称为历史搜索快照。
3. 禁止用 gold 的证据清单为代理筛选搜索空间、排名或可打开页面。维护进程若预取 gold 引用页，只能作为完全透明缓存，不暴露清单/命中状态、不改变搜索结果；默认按代理工具请求取页。
4. 普通页完整返回；超长页按固定解析后的段落边界分页，不按当前问题 BM25 过滤。分页算法和长度上限各臂相同、主实验前固定，优先使用与模型无关的字符/字节规则。每一页段是完整逻辑文档 `d=(pageid,revid,part,hash)`；不得把被截断页面称为完整页面。
5. 基础工具：`search(query)` 仅返回 top-10 标题、ID、链接，不向模型返回当前页面的事实摘要，避免用 2026 摘要旁路历史正文；当前标题/排名仍可能漂移，不能当作历史事实证据。`open(page_id,part)` 返回完整逻辑文档及分页指针；`notes_read/write` 仅访问本题笔记；`close(doc_id)` 按冻结策略移出原文。无额外付费 web-search 工具。
6. T0/T1 搜索结果增加 `Cat(d)=distinct(s,r,kappa)`；`read_objects` 按主体、关系或二者查询，返回规范值、原值、证据和列表状态。不做 SQL，不在命中不足时阻止打开原文。
7. 上下文预算、每题最大步数/输出、超限处置在 M4 前固定本轮试点版本，允许试点版本迭代，M4 后/M5 前最终冻结。关闭文档会改变后续前缀，必须记录；不能为治疗臂选择性压缩。超限按相同规则处置，不默默丢弃样本。

### 3.2 分叉和缓存

- 只在代理实际 `open` 后触发；不为 cracking 单独打开文档，也不以 HOT_ONLY 准入来筛掉 cache miss。
- 共享 prefix 包括 system/developer、工具/schema、当前题、已发生的消息与已打开文档。T0/T1 的共同说明预置在其系统指令中；fork 在 prefix 后追加角色切换和该文档历史查询，不能替换 prefix 内的 system。
- 为避免并行双 miss，拟在包含文档的正常回答 continuation 返回后，异步发出 fork；后续回答步骤不等待 fork。本题完成后设持久化屏障，下一题才开始。这是调度选择，不声称与论文内部 serving 相同。
- 保存 prefix 序列化哈希、parent attempt、fork attempt、doc ID、调度/首 token/完成时间和原始 usage。相同哈希只证明本地输入相同；只有供应商 usage 能证明计费缓存命中，不能推断整份文档的 KV 精确命中。
- OpenRouter 固定 endpoint 与服务层，禁自动 fallback。检查实际响应路由、reasoning 回传、结构化输出参数与工具参数是否改变缓存。目录标价、显式断点或 sticky session 都不是命中保证。
- 在最早的应用可控 prefix 放置固定格式、与题目内容无关的 `(experiment,model,arm,group)` namespace；同一 parent/fork 保持一致，不同臂/组不同。M2 检查各 namespace 的 token 长度差并控制格式，以受控 probe 比较同/异 namespace 的计费命中量；不能由总 cached_tokens 推断文档段的精确命中。可额外设置 provider cache key，但不能只依赖路由 key。所有臂（含 B0）都承担此开销；否则 T0/T1 互相预热而 B0 无此收益，会污染 C1。namespace 不保证隐藏系统/共享工具前缀绝对零命中，此部分另记。
- 草案总 cracking 输出预算 **4096 tokens/题**，包括供应商计费的 reasoning 输出。多 fork 必须先原子预留，再按 usage 退回未用额度，不能并发超配。每 fork 份额/最小剩余额度在试点冻结；耗尽后记录 `budget_exhausted`，不再开新请求。每个已执行 fork 看到其完整逻辑文档，不意味着预算允许抽出所有关系。
- 首选 schema 约束 JSON。若 API 参数破坏前缀/不可用，允许改为提示约束 JSON + 本地校验，但必须记录偏差、重新烟测、在主实验前冻结，不能把它称为供应商强制结构化输出。截断或不合法 JSON 默认整次不发布，不用模型补写残缺列表。

### 3.3 对象模型与校验

研究对象基于 `c=<s,r,o,kappa,u,epsilon>`，E/R 开放，不依赖财务白名单。

| 字段 | 内容 |
| --- | --- |
| s / r | 原始标签、规范化标签，优先保留文档原称；大小写/Unicode/空白规范化规则固定 |
| o | entity 或带类型的 str/int/date；保留原值和规范值，不以浮点数存精确整数 |
| kappa / u | singular 或 list、原始和规范化单位；小数不偷偷转整数，新增 decimal 类型需单独 schema 版本 |
| epsilon | doc ID、正文 hash、quote 与精确位置，必要时主体/关系各自证据片段 |
| provenance | 当前 query ID、fork attempt、model/endpoint、prompt/schema 版本、创建时间 |
| list group | group ID、model-declared complete、成员数、一次提交/事务 ID |
| requestedness | requested / speculative / uncertain，自报标签，不是已证实的未来价值 |
| trust tier | GROUNDED；VALIDATED 为后续领域插件保留 |

GROUNDED：schema/type 合法，引用在**同一完整逻辑文档**逐字定位，原值可从引用按公开规则映射到规范值；保存原文而非用规范化后的近似匹配冒充 verbatim。主体出现和数值出现不证明 `(s,r,o)` 的语义关系成立，这由后续人工审计/领域验证判断。

列表必须一次声明完整、所有成员有证据、整体校验通过才原子入库并展开边；任一成员无证据则整组拒绝。`model-declared complete` 不能显示为已证明完整。读取必须返回完整组或明确提示超限/不可用、引导回退，不能将分页子集当完整答案。去重不能破坏组成员数；多个来源或冲突列表保留来源，不默默合并为更大“完整列表”。

### 3.4 研究存储与日志

SQLite 建议表：`documents`、`cracking_runs`、`objects`、`list_groups`、`document_queries`、`object_reads`、`call_ledger`、`run_events`。隔离键至少是 experiment/model/arm/group；不同臂不能共享对象。corpus 字节缓存可共享，供应商 prompt cache 状态不可伪称完全隔离。

查询历史只记录已经开始的题及其 open/read 事件。可读对象使用每题开始的 snapshot，当前题 forks 延后发布到下一题可见快照，消除异步完成时间影响本题答题的竞态；这是本协议的保守实现。R 结束屏障后 Q 能读 R 的对象，Q 产生的对象仍付费且归档，但本两题实验内不再消费。

### 3.5 多模型账本与评测

- 所有角色经过同一个研究账户准入：answer、cracking、generator、judge、probe。原子持久化预留上界后才发请求；settle 幂等；超时、usage/cost 缺失、路由不符、进程中断不能当 0 元。
- OpenRouter 保存 generation ID、实际 endpoint、原始 `usage`、reported cost、cached/write/reasoning 用量及价格快照。精确字段以 M2 实测归一化，缺字段标 null，不凭猜测补零。
- 本地 token 分解成本、OpenRouter reported cost、最终平台对账是三种证据；充值费/汇兑不混入推理成本。UNKNOWN 保留预留占用并停派；对账明确后维护者恢复，不自动重试。
- 独立 SQLite 存储仍须汇总历史开销；本轮不改旧 Go 预算、provider CHECK 或 CNY 账本。
- Scorer 固定 FanOutQA commit，保留 `acc.loose`、`acc.strict` 和 GPT judge。未作答也进入分母；无 judge key/失败不能把上游默认 0 当真实 judge 分数。
- OpenRouter judge 配置映射：`FANOUTQA_OPENAI_API_BASE=https://openrouter.ai/api/v1`，`FANOUTQA_JUDGE_MODEL=openai/gpt-4o-2024-11-20`，密钥由环境注入。Kani 的 tokenizer/模型别名兼容和所有 judge 调用计费在 M2 验收；若需 adapter，保留原评分 prompt 与解析规则，并记录源码摘要。
- 准确率测试不要求 BLEURT/ROUGE；不要直接调用会隐式下载其他模型或绕开研究账本的全量 scorer。gold 只在离线评测进程挂载。

## 4. 里程碑验收

| 阶段 | 可检查的退出条件 |
| --- | --- |
| M0 | 来源/哈希、210 题选集（12 试点/198 主集，另 100 题保留）、臂、主张、计费口径、停止规则、未知项全部落盘；标为草案而非冻结 |
| M1 | 离线闭环与依赖锁；B0/T0/T1 使用同一工具基础；测试信息隔离、完整列表原子性、去重、规范化、prefix hash、并发预算、UNKNOWN 和幂等恢复；接入 `scripts/check_python.py` |
| M2 | 无 gold 的试点烟测，验证真实模型/endpoint、key 权限、工具、reasoning、显式缓存/输出 schema、cache usage 和费用对账；给出支持矩阵，不仅“能回答” |
| M3 | 所有目标题有核验通过的相关题或明确失败记录；生成器看不到 gold/系统设计；工作负载与核验表冻结且许可清楚 |
| M4 | 按协议工程门槛决定继续；试点可调，独立主集不可用于调参；冻结所有 nullable 运行参数及附加臂规模 |
| M5 | 逐组按冻结顺序运行，记录全部费用和缺失；中断后按原 ID/账本恢复；运行时不根据效果加题或改 prompt |
| M6 | 原始指标、配对区间、失败/截断比例、对象审计、两种成本口径齐备；无法判定如实报告；发布只含审查过的数据 |

最低离线回归还应覆盖：R/Q 会话重置、未来题阻断、gold 分解不进入 corpus 导航、没有提前 cracking、供应商被切换时拒绝继续、cost=0 与 cost=null 的区别、列表被截断后无法读到半组、阶段上限不随新建 store 重置。

## 5. 产品移植要点（v0.4）

这些是目前代码检查所得的风险记录，**不是本轮实施任务**：

- 新建开放 `cracked_objects`/列表组/查询历史结构，勿硬塞财务 `facts(entity,concept,period,value numeric)`。保留 version/evidence、originating query、fork、tier 和撤销关系。迁移号在实施时分配；当前最后一个是 `00015`，不保证届时下一个仍是 `00016`。
- 为 cracking 建独立计费 stage。现行 `llm_calls.stage` CHECK 与 `admitM2Stage` 只认 answer/extraction/mapping/probe/other；extraction 与 batch、M3 缓存调度、M4 恢复耦合，不能只改字符串就复用。
- 候选 RPC：`GetCatalogue`、`ReadObjects`（s/r/s+r）、`StoreCrackedObjects`；Go 负责权限、版本、证据和列表原子发布，金融语义验证作为升级插件。
- `query_runs.provider` 目前只认 mock/deepseek，预算表只有 CNY，`evidence_regions` 要求 page/bbox。多供应商、USD、网页文档须明确设计，不伪造 PDF 坐标或静默换算费用。
- 原白名单、小候选数、HOT_ONLY 是历史产品选择，不是研究算法要求。产品默认信任策略须由 v0.3 的质量与风险结果决定。
