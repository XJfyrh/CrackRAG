# 简历项目说明

**CrackRAG：有证据约束、可复用事实的财务文档问答系统**

技术栈：Go、Python、PostgreSQL/pgvector、Redis、React、Docker Compose、BGE-M3、DeepSeek。

以下描述可按岗位与本人负责部分调整：

- 设计模型结构化声明与 Go 权威验证分离的回答链路，核验实体、年度列、单位、合并口径和逐字引用；缺证据明确弃答，避免自由正文绕过校验。
- 将后台候选抽取、验证报告和正式事实发布分离，结合数据库事务、租约及 fencing 支持中断恢复；有效事实 FULL 命中直接生成答案，零模型调用。
- 交付 Linux CPU Docker Compose 首发、完整浏览器演示和真实模型证据；两个来源的 12 项独立质量用例通过，另 16 条费用序列答案核对通过，构建后的 4 个重复/改写查询均零模型调用。

本轮序列累计费用估算下降 8.59%，样本仅两家公司、四问序列；此前另一批曾增加 16.65%。面试中应解释前期构建开销、供应商缓存波动和适用条件，不能写成“普遍节省 8.59%”或行业准确率。

演示顺序：默认 mock 启动 → 上传自制 PDF → 首问与来源 → 显式 COLD 构建 → FULL 复用 → 缺证据弃答 → 历史刷新 → HOT 策略 → 故障恢复。真实证据见 [验收记录](release-validation.md)，录像和校验文件在 [v0.1.0 Release](https://github.com/XJfyrh/CrackRAG/releases/tag/v0.1.0)。

可解释的工程取舍：限定财务标量范围，优先可核验性；数据库为权威状态，Redis 仅通知；未知费用阻止新派发；默认本机、mock、无供应商密钥，真实模式显式准备。首版不宣称支持 OCR、复杂跨页推理或公网生产运营。
